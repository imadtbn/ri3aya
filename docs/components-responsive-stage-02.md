# المرحلة 02 — توحيد المكونات والتجاوب

تاريخ التنفيذ: 2026-10-12

## ما تم الحفاظ عليه

تستخدم الصفحات بالفعل القشرة المشتركة `shared-v2` مع الهيدر والهيرو والفوتر؛ لم تُستبدل القوالب أو تُعدّل المحتويات الطبية أو ترتيب أقسام الصفحات. لم يتم إنشاء نظام CSS جديد أو تعطيل CSS المتخصص.

## التحسينات المنفذة

1. **الهيدر والقائمة:** تأمين عرض الشعار والبحث ضمن عرض 320px، وإظهار القائمة المحمولة كلوحة منسدلة فوق المحتوى عند <=992px دون دفع الهيرو للأسفل. القائمة قابلة للتمرير إن طالت. زر القائمة يبدل الرمز والاسم القابل للقراءة، وتُغلق القائمة بالنقر خارجها أو Escape أو تمرير الصفحة؛ وإغلاقها يعيد حالة القوائم الفرعية.
2. **الهيرو:** الحفاظ على النسق والألوان القائمة مع منع تجاوز العناوين ومسار التنقل وإتاحة التفاف أزرار الهيرو دون قص.
3. **الفوتر:** منع اختناق أعمدة الروابط على الهاتف؛ تتحول إلى عمود واحد تحت 480px، وتتكيف أزرار PWA ومربع الإرشادات مع العرض.
4. **البطاقات:** تحسين حدود العرض ومحاذاة أزرار بطاقات المكتبة والأدوات فقط. إصلاح قاعدة عامة قد تعيد حشوة إلى بطاقات الرئيسية المصورة، بحصر حشوة الهاتف في البطاقات النصية المحددة وصفحة الأقسام.
5. **الجداول:** حصر التمرير الأفقي داخل حاويات الجداول المعروفة، مع الإبقاء على البنية الأصلية والوصول عبر لوحة المفاتيح.
6. **PWA:** تغيير إصدار التخزين المؤقت إلى `ui-components-20261012-v3` حتى تصل CSS وJavaScript الجديدتان للمستخدم عند اعتماد تحديث التطبيق.

## الاختبارات

- **تم تنفيذ فحص مصدر حي عبر موصل GitHub:** التحقق من وجود مكونات header / hero / footer / nav / search في 28 ملف HTML، دون عناصر ناقصة في هذه العينة.
- **تم التحقق من JavaScript نحويًا:** الشيفرة الجديدة في `js/main.js` قابلة للترجمة.
- **تم توسيع `scripts/check_css_stability.mjs`:** إضافة فحوص ثابتة لبنية `shared-v2` ولعدم عودة الحشوة العامة وارتباط أزرار القائمة بحالتها.
- **تم توسيع `scripts/check_layout.mjs`:** فحوص Playwright على 320 و360 و390 و768 و1024 و1440 بكسل، لتجاوز الهيدر والفوتر، وتموضع القائمة، ومقاس زرها، وثبات موضع الهيرو، والإغلاق بالنقر خارج القائمة وEscape والتمرير. ويظل الاختبار الموجود للجداول القابلة للتمرير بلوحة المفاتيح قائمًا.

**حالة التنفيذ الفعلي لاختبارات المتصفح:** لم تُشغّل مجموعة Playwright على الموقع الكامل أثناء هذه الجلسة؛ تعذر استنساخ المستودع داخل بيئة المتصفح بسبب خطأ DNS في github.com، رغم نجاح الوصول عبر موصل GitHub. وجود اختبار برمجي لا يُعادل نجاحه.

## خطوات القبول قبل اعتماد المرحلة

```bash
gh repo clone imadtbn/ri3aya
cd ri3aya
node scripts/check_css_stability.mjs
python scripts/sync_layout.py --check
npm install --no-save playwright
CHROMIUM_PATH=/usr/bin/chromium node scripts/check_layout.mjs
```

يلزم فتح الصفحات الأساسية والجانبية على الهاتف والتحقق من القوائم والبطاقات والجداول، خاصة `nutrition.html` و`crying.html` بعد تصحيح عرض الشريط الجانبي في المرحلة السابقة. لن تعتبر المرحلة مختبرة بصريًا حتى تنجح هذه الأوامر والفحص اليدوي.
