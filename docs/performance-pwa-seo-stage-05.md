# المرحلة 05 — الأداء وPWA وSEO والإعلانات

تاريخ التنفيذ: 12 أكتوبر 2026

## الهدف والنطاق

تثبيت بنية مشروع `ri3aya` قبل اختبارات القبول النهائية، دون إعادة تصميم الصفحات أو تعديل محتواها الطبي أو إضافة ميزات جديدة.

## التعديلات المرفوعة

| المجال | الإصلاح |
|---|---|
| PWA | الموارد الحرجة (HTML وCSS وJavaScript وJSON وCSV) تُحفظ ضمن دفعات لا تتجاوز 12 طلبًا. فشل أي مورد حرج يُوقف تثبيت النسخة الناقصة بدل الإعلان كذبًا عن اكتمالها. |
| صور PWA | تُحمّل الصور الثانوية بحد أقصى 5 طلبات متزامنة، وفشل صورة واحدة لا يُفشل تثبيت النسخة النصية الكاملة. |
| الأداء | عدم التحميل المسبق لبعض نسخ الصور المتجاوبة المكررة (320/960 WebP في `images/optimized/`). تُحفظ الصور التي يطلبها المستخدم لاحقًا في Cache عند نجاح جلبها. |
| إعلانات AdSense | التحقق من الصيغة الفعلية لمعرّف `ca-pub` ورقم الوحدة، إخفاء المعرّفات الوهمية، وعدم استدعاء الوحدة إذا عرضها أقل من 250 بكسل. |
| الإعلانات غير المعبأة | تُخفى الحاويات ذات الحالة `data-ad-status="unfilled"` عبر CSS بدل عرض مساحة بيضاء. |
| sitemap | تحديث `lastmod` إلى 2026-10-12 لصفحات النوم والتغذية والتلقيح والنمو والأمراض والأدوات وسياسة التحرير التي تغيرت فعليًا. |
| الروابط | إضافة `scripts/check_internal_links.py` لفحص جميع روابط الملفات المحلية والصور والـ srcset وخلفيات CSS وأهداف الروابط ذات الـ `#fragment` في كامل الصفحات. |
| الاختبارات | إضافة `scripts/test_stage05.cjs` وتوسيع `scripts/check_pwa.mjs` لاختبار تعطل صورة اختيارية أثناء تثبيت PWA. |
| التخزين المؤقت | تحديث `pwa/config.js` إلى `stage05-perf-pwa-seo-20261012-v7`. |

## الفحوص التي أُنجزت على مصدر GitHub مباشرة

- قراءة **28 ملف HTML** في أربع مجموعات والتحقق من مراجعها الداخلية مقابل قائمة موارد النسخة المنشورة، دون العثور على روابط ملفات محلية مفقودة في هذه الجولة.
- التحقق من وجود `canonical` واحد لكل صفحة.
- تحليل **34 مقطع JSON-LD** بنجاح دون أخطاء تركيبية.
- التحقق من المقاطع الداخلية `pages/privacy.html → tools.html#local-data-panel` و`pages/tools.html → digestive.html#symptom-tracker`.
- التحقق نحويًا من `service-worker.js` و`js/site-tags.js` بعد التعديل.
- تشغيل محاكاة وظيفية لأحداث إعلان مهيأ، وإعلان بمعرّف تجريبي، وحاوية بعرض 81 بكسل؛ تحقق الاختبار من عدم طلب AdSense عند المعرف الوهمي أو العرض الضيق.
- إصدار PWA يحتوي على 131 مسار مورد، لكن أصبح بعضها يُجلب فقط عند الحاجة.

**هذه الفحوص لا تعادل اختبار Lighthouse أو نجاح تثبيت Service Worker داخل متصفح حقيقي.**

## حالة الإعلانات الحالية

معرّفات AdSense في `js/site-tags.js` ما زالت `xxxxxxxxx`. لذلك تبقى الوحدات مخفية، ولا توجد إمكانية للتحقق من تعبئة إعلان حقيقي حتى تُضبط حسابات/وحدات صالحة. لم تُخترع معرفات ولم تُنقل معرفات من موقع آخر دون مراجعة إعدادات الموقع.

## شروط قبول المرحلة

```bash
python scripts/check_seo_pwa.py
python scripts/check_internal_links.py
node scripts/test_stage05.cjs
node scripts/test_tools.cjs
node scripts/test_local_data.cjs
node scripts/test_stage04.cjs
node scripts/check_css_stability.mjs
node scripts/check_medical_safety.mjs

# يتطلب Chromium وPlaywright على نسخة كاملة من المستودع:
CHROMIUM_PATH=/usr/bin/chromium node scripts/check_pwa.mjs
CHROMIUM_PATH=/usr/bin/chromium node scripts/check_layout.mjs

# لإعادة إنشاء نسخة PWA ببصمة فعلية من جميع الملفات:
python scripts/build_pwa.py
python scripts/build_pwa.py --check
```

**ملاحظة مهمة:** إصدار PWA المرفوع حاليًا تحديث دلالي يدوي ضمن `pwa/config.js`، ولا يُعتبر ناتجًا عن إعادة تشغيل `build_pwa.py` بالبصمة الآلية. يجب إعادة توليد `pwa/config.js` باستخدام أداة البناء من نسخة محلية كاملة بعد آخر التعديلات، ثم تشغيل `--check` قبل إصدار إنتاجي معتمد. لا يجوز الادعاء بأن اختبار البصمة قد نجح الآن.

## قياسات الأداء المنتظرة في مرحلة القبول

- LCP وINP وCLS عبر Lighthouse أو بيانات المستخدمين الحقيقية.
- عدد الطلبات وأحجام تحميل الصفحة الرئيسية وصفحات النمو/النوم/التغذية.
- اختبار PWA عند قطع الاتصال، وتحديث إصدار جديد مع الحفاظ على سجلات الطفل المحلية.
- التحقق من سلوك الإعلانات إن تم تفعيل حساب صالح، خصوصًا على عرض 320 و360 بكسل.
- التحقق من روابط ومخططات SEO في متصفح إنتاجي ومراجعة فهرسة الصفحات.
