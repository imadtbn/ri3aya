# المرحلة 04 — تأهيل الأدوات والبحث

تاريخ التنفيذ: 12 أكتوبر 2026

## النطاق

فحص الحسابات ومدخلات المستخدم وفلترة الأدوات ومحرك البحث العربي وبيانات المتابعة المحلية والتصدير والحذف. لا تغييرات على الهوية البصرية ولا إضافة أدوات تشخيصية أو جرعات علاجية.

## الإصلاحات التي رُفعت

| المكوّن | المشكلة | التحسين |
|---|---|---|
| `js/tools-index.js` | عمر غير صالح يُظهر رسالة خطأ لكنه يترك نتائج الفلترة القديمة | إخفاء نتائج الأدوات عند الإدخال غير الصالح؛ التحقق من الأعداد الصحيحة 0–36 شهرًا؛ استعادة النتائج بعد تصحيح القيمة |
| `js/nutrition.js` | تاريخ حفظ الطعام غير مكتمل التحقق ويستخدم وقت UTC كمرجع | مقارنة التاريخ المحلي، والتحقق من اليوم الفعلي، ورفض التواريخ المستقبلية أو غير الموجودة دون مسح حقول الإدخال |
| `js/vaccine.js` | العمر يُحسب بالقسمة على 30.4375 يومًا بدل الأشهر التقويمية، ويمكن أن يتأثر بالمناطق الزمنية | حساب الشهور التقويمية المكتملة والتحقق من تاريخ الميلاد الحقيقي والمستقبلي |
| `js/growth.js` | رسائل حساب النمو تعرض تفاصيل داخلية، ويمكن إدخال قياس بتاريخ مستقبلي | صياغة رسائل مناسبة للمستخدم، ورفض التاريخ المستقبلي مع الحفاظ على البيانات الموجودة |
| `js/local-data.js` | الغموض بين حذف عنصر وحذف مجموعة، وبين طلب تنزيل الملف وإتمامه، وبين الحذف الكامل والجزئي | توضيح أسماء الأزرار وحالات الفشل وحماية السجلات؛ دون مسح بيانات المواقع الأخرى |
| `scripts/check_layout.mjs` | نقص اختبارات تواريخ النمو والطعام وأعمار فلتر الأدوات | إضافة سيناريوهات ترفض التاريخ المستقبلي والقيم الكسرية والسالبة وتضمن عدم حفظ النتائج غير الصحيحة |
| `scripts/test_stage04.cjs` | عدم وجود اختبارات محددة لتواريخ التلقيح وسلوك مدخلات الطعام | إضافة 21 اختبارًا حتميًا ضمن محاكاة Node/DOM، دون خادم خارجي |

## التحقق الفعلي الذي أُنجز أثناء التنفيذ

اختبرت شفرة المستودع التي تم جلبها من GitHub داخل بيئة JavaScript مع محاكاة للمدخلات:

- **21 فحصًا** من اختبارات المرحلة 04 في بيئة معزولة بمكافئات لواجهات Node القياسية؛ تشمل البحث العربي، عمر أداة المتابعة، تاريخ الميلاد، تواريخ الطعام، والرسائل.
- **12 فحصًا** للتخزين المحلي، مثل الحفظ والقراءة وحذف سجل محدد وتصدير JSON/CSV وحماية خلايا CSV والتصدير الخام عند فساد البيانات وفشل التخزين.
- **10 فحوص** لحساب WHO الفعلي باستخدام manifest وملفات LMS الأربعة المخزنة في المستودع للذكور؛ تشمل Z-score، النسب المئوية، القيم غير الصالحة، ومنع إعادة تحميل البيانات المحفوظة.
- **28 فحصًا** لمولد الروتين: ست فئات عمرية وأربعة خيارات للقيلولات وحالات المخرجات بعد منتصف الليل والمدخلات غير الصالحة.

هذه اختبارات وحدات حقيقية لمنطق JavaScript وملفات البيانات، لكنها ليست تنفيذًا لمتصفح Chromium على كل صفحات الموقع؛ كما أن بعض الحالات متداخلة مع سيناريوهات الأدوات القائمة.

## اختبارات المستودع القابلة للتكرار

```bash
node scripts/test_stage04.cjs
node scripts/test_tools.cjs
node scripts/test_local_data.cjs
node scripts/check_medical_safety.mjs
node scripts/check_css_stability.mjs
# يتطلب Playwright وChromium ونسخة كاملة من المستودع
CHROMIUM_PATH=/usr/bin/chromium node scripts/check_layout.mjs
```

`check_layout.mjs` يختبر فتح الصفحات في عروض 320 و360 و390 و768 و1024 و1440، وإدخال بيانات غير صالحة، وسجل الطعام والنمو، والتصدير والحذف، والتحكم عبر لوحة المفاتيح، مع تسجيل أخطاء JavaScript.

## خصوصية البيانات والتصدير

- السجلات محفوظة محليًا في المتصفح فقط ولا ينبغي إرسالها إلى خادم دون موافقة المستخدم.
- يحفظ `exportData` البيانات بصيغة JSON أو CSV ولا يفترض أن البيانات الفاسدة سجلات فارغة.
- يتطلب حذف السجلات موافقة صريحة؛ وبقيت البيانات خارج مفاتيح التطبيق دون تعديل.
- يجب الاحتفاظ بنسخة مصدّرة قبل حذف البيانات؛ لا توجد استعادة تلقائية للحذف.

## ما لم يكتمل

تعذر سحب المستودع كاملًا إلى بيئة Chromium لأن `github.com` لم يُحل عبر DNS، لذلك **لم أُشغّل مجموعة المتصفح الشاملة**؛ ولا ينبغي إعلان نجاح جميع اختبارات الواجهة أو اعتماد المرحلة نهائيًا قبل ذلك.

يلزم أيضًا إعادة توليد `pwa/config.js` من `scripts/build_pwa.py` خلال مرحلة الأداء وPWA. تم رفع تغيير رقم الإصدار يدويًا لضمان تجديد التخزين المؤقت، ولا تعادل تلك الخطوة بناءً تجريبيًا يتحقق من البصمات الرقمية.

## الحالة

أُنجزت تصحيحات المرحلة ورفعها والتحقق من شفرتها واختبارات الوحدات المذكورة. قبول المرحلة كإصدار إنتاجي نهائي معلق لحين تشغيل اختبارات المتصفح والتحقق من مسارات التنزيل على الهاتف.
