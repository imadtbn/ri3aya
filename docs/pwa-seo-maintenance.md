# صيانة الأداء والنسخة دون اتصال وSEO

## البناء بالترتيب

```bash
python scripts/sync_layout.py
python scripts/build_articles.py
python scripts/build_pwa.py
python scripts/sync_layout.py --check
python scripts/build_articles.py --check
python scripts/build_pwa.py --check
python scripts/check_seo_pwa.py
python scripts/quality_gate.py
```

يجب بناء PWA أخيرًا بعد استقرار جميع صفحات HTML والأصول. `pwa/config.js` مولد، ويحمل مسارات عامة وبصمة إصدار مشتقة من محتويات الملفات وعامل الخدمة. لا تعدّل البصمة يدويًا ولا تضف بيانات شخصية إلى قائمة الملفات. حد اللقطة 6 ميبيبايت دون ضغط النقل.

## النسخة المتسقة والتحديث

عامل الخدمة يحتفظ بلقطة ملفات واحدة ويقدمها من الذاكرة عند الطلب؛ يبدأ تجهيز إصدار جديد في الخلفية، ثم يبقى منتظرًا ما دامت النسخة الحالية مستخدمة. زر التحديث يطلب حفظ المدخلات قبل التفعيل وإعادة التحميل. أول زيارة تحتاج اتصالًا حتى يكتمل حفظ جميع الملفات. النسخة المحفوظة ليست ضمانًا لأحدث معلومات منشورة؛ يحتاج المستخدم إلى الاتصال وقبول التحديث. لا تضمن ذاكرة المتصفح الدوام، ولا تحل محل نسخة مصدرة من السجلات.

ملفات HTML ذات معاملات بحث تشترك في نسخة الصفحة الثابتة؛ تبقى المعاملات في عنوان المتصفح. لا تتضخم الذاكرة مع كل تركيب فلاتر. المسارات خارج بادئة المشروع والطلبات الخارجية خارج معالجة العامل. تنظيف الذاكرة يخص `ri3aya-pwa-` وأسماء `ri3aya-v` القديمة فقط، ولا يلمس localStorage أو ذاكرات مشاريع أخرى.

الصفحة البديلة تُفتح بمسارها الحقيقي، حتى لا تنكسر روابطها عند طلب مسار متداخل. ملفات JSON/CSV المفقودة لا تستبدل بصفحة HTML. الفشل في تجهيز إصدار كامل لا يفعّل نسخة ناقصة. لا يعتمد الموقع على الإنترنت لقراءة المقالات أو تصفية البحث أو حساب WHO بعد اكتمال اللقطة؛ الخطوط والأيقونات الخارجية ورسم Chart.js والخدمات المتصلة قد تحتاج اتصالًا.

## الصور والبيانات الوصفية

`images/optimized/catalog.json` يربط الصور الأصلية بنسخ WebP. ولدت النسخ باستخدام ImageMagick `convert` مع resize وstrip وquality 78؛ لا تحذف المصادر قبل التحقق من المواضع غير المولدة. يولد `scripts/site_metadata.py` المطابقات وsrcset والتثبيت وبيانات المشاركة وBreadcrumbList من التنقل الفعلي. لا تضف اسم مراجع طبي أو تاريخ مراجعة ضمن SEO ما لم توجد مراجعة مثبتة في المصدر التحريري.

الفهرسة تخص الروابط المستقلة الثابتة. صفحة البحث ليست وجهة للفهرسة ولا تدخل خريطة الموقع. تؤكد الاختبارات فرادة العناوين والروابط ووجود صور المشاركة وصحة JSON-LD، لكنها لا تضمن قبول نتائج غنية أو تحسين ترتيب البحث.

## الاختبارات والمتابعة بعد النشر

```bash
node scripts/test_search.cjs
node scripts/test_local_data.cjs
node scripts/check_layout.mjs
node scripts/check_pwa.mjs
```

تحتاج اختبارات المتصفح إلى Playwright وChromium خارج اعتماديات الإنتاج، ويدعم السكريبتان `PLAYWRIGHT_MODULE` و`CHROMIUM_PATH`. CI يثبت Playwright بإصدار محدد والمتصفح ويشغل اختبار العرض والأدوات، ثم اختبار عامل خدمة فعلي تحت بادئة GitHub Pages مع الشبكة المتاحة والمفصولة وتحديث إصدارين.

اختبار طلب التثبيت محاكى للتحقق من واجهة القبول والإلغاء؛ لا يعادل تثبيتًا أصليًا على Android أو iOS. بعد النشر، اختبر التثبيت والتحديث والتصدير على هاتف فعلي، ثم قس LCP وINP وCLS في النسخة الحية مع الخطوط والتحليلات والإعلانات الفعلية. أرقام حجم الملفات في تقرير الإنجاز لا تعادل درجات Lighthouse أو بيانات مستخدمين حقيقية.

المراجع التقنية: [دورة عامل الخدمة](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)، [طلب التثبيت](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeinstallprompt_event)، [مسار التنقل المنظّم](https://developers.google.com/search/docs/appearance/structured-data/breadcrumb).
